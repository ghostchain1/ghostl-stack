# Secrets Model (L1/L2/L3)

Last updated: 2026-02-04

## Canonical Env Files
- L1: `infra/ghostchain/.env.l1`
- L2: `infra/opstack/.env.l2`
- L3: `infra/opstack/.env.l3`

These are the **authoritative** inputs for env sync scripts:
- `infra/scripts/env-sync-l1.sh`
- `infra/scripts/env-sync-l2.sh`
- `infra/scripts/env-sync-l3.sh`

## Secrets Sources
Each layer supports:
- `dev` (explicit opt-in only via `ALLOW_DEV_SECRETS=1`)
- `vault` (preferred for staging/prod)

## Vault Integration

### L1
- Script: `infra/vault/render-l1-secrets.sh`
- Env:
  - `L1_SECRETS_DIR` (output path)
  - `VAULT_L1_PATH` (default: `ghostchain/l1`)
- Required keys in Vault:
  - `bootnode_key`
  - `node1_key`
  - `node2_key`
  - `jwtsecret`

### L2
- Script: `infra/vault/render-l2-secrets.sh`
- Env:
  - `L2_SECRETS_DIR` (output path)
  - `VAULT_L2_PATH` (default: `ghostchain/l2`)
- Required keys in Vault:
  - `sequencer_key`
  - `batcher_key`
  - `proposer_key`
  - `challenger_key`
  - `jwtsecret`

### L3
- Script: `infra/vault/render-l3-secrets.sh`
- Env:
  - `L3_SECRETS_DIR` (output path)
  - `VAULT_L3_PATH` (default: `ghostchain/l3`)
- Required keys in Vault:
  - `sequencer_key`
  - `batcher_key`
  - `proposer_key`
  - `challenger_key`
  - `jwtsecret`

## Dev Mode Guardrails
- `ALLOW_DEV_SECRETS=1` must be set for dev secrets.
- Env sync scripts fail hard if placeholders or weak defaults are detected.

## Operational Flow
1. Populate `.env.l1`, `.env.l2`, `.env.l3`.
2. Render secrets (Vault):
   - `infra/vault/render-l1-secrets.sh`
   - `infra/vault/render-l2-secrets.sh`
   - `infra/vault/render-l3-secrets.sh`
3. Run env sync:
   - `infra/scripts/env-sync-l1.sh`
   - `infra/scripts/env-sync-l2.sh`
   - `infra/scripts/env-sync-l3.sh`

## Notes
- `infra/opstack/.env` is a **derived** file for L2, generated by `env-sync-l2.sh`.
- `infra/opstack/.env.l3.generated` is the derived file for L3, generated by `env-sync-l3.sh`.
