## Primary compose entrypoints
- Root stacks: `docker-compose.yml`, `docker-compose.dev.yml`
- Core service stack: `core-service/docker-compose.yml`
- OP Stack: `infra/opstack/docker-compose.yml`, `infra/opstack/docker-compose.l3.yml`, `infra/opstack/docker-compose.challengers.yml`, `infra/opstack/docker-compose.network-manager.yml`, `infra/opstack/docker-compose.mainnet-geth.yml`
- L1 geth PoA: `infra/ghostchain/docker-compose.l1.yml` (legacy IBFT in `infra/ghostchain/docker-compose.ibft.yml`)
- Observability: `observability/infra/docker-compose.yml` and OP Stack observability profile in `infra/opstack/docker-compose.yml`
- Service stacks: `services/*/docker-compose.yml` (numerous microservices; see `services/`)
- App stacks: `apps/docker-compose.yml`, `apps/docker-compose.dev.yml`

## Client containers (consensus boundary)
- L1: geth bootnode + two signers (clique PoA)
- L2: `op-geth`, `op-node`, `op-batcher`, `op-proposer`, `op-gate`
- L3: `l3-geth`, `l3-op-node`, `l3-op-batcher`, `l3-op-proposer`
- Challengers: OP Stack challenger services (optional overlay compose)

## Governance + protocol contracts
- Governance core: `contracts/src/governance/Governor.sol`, `contracts/src/governance/ProposalExecutor.sol`
- L1 protocol stubs (staking/slashing/treasury/native token): `contracts/src/futuristic/FutureStack.sol`
- Common access controls: `contracts/src/common/` (Governed/Ownable/AccessManaged patterns)
- Compliance/guards: `contracts/src/compliance/`

## Monitoring stack
- Prometheus + Grafana profiles in OP Stack compose (`infra/opstack/docker-compose.yml --profile observability`).
- Additional observability compose in `observability/infra/docker-compose.yml`.
- Service-level telemetry and status APIs are scattered under `services/*`.

## Key management
- Local dev keys: `.env` / `.env.secrets` in `infra/opstack/`, generated by `infra/scripts/opstack/keys/init.sh`.
- Production guidance (Vault/KMS/HSM) is documented in `docs/SECRETS.md` and checklists, but not enforced in code.

## Consensus boundary summary
- Consensus/P2P/state transition live in geth/op-geth/op-node clients (external binaries).
- This repo provides orchestration, governance, and monitoring layers; it does not alter consensus engines.
